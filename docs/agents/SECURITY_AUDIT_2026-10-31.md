# A-05 — проверка безопасности детских фотоотчётов (31.10.2026)

**Статус аудита: выполнен. Статус публичного выпуска: BLOCK.** Исследован только локальный код пилота `server/photos.py` и `js/photos.js`. Реальные фото, база данных, ключи и пользовательские данные не читались.

## Результат автоматической проверки
- 12 статических эвристик: **5 PASS, 7 RISK**.
- Подтверждены по исходному коду: выборка задачи ограничена семьёй/ребёнком; выдача фото требует роль родителя; токены генерируются случайно и хранятся как хэши; приглашения имеют срок действия и одноразовое погашение; ограничен объём загрузки.
- Отсутствуют полноценные операции **отзыва устройства**, **удаления всей семьи** и **очистки резервных копий**.
- Токен доступа хранится в `localStorage` браузера, значит доступен скриптам на странице.
- В Python-сервисе не обнаружен собственный лимит частоты запросов на приглашения/создание семьи (ограничения прокси не проверялись).
- JPEG проверяется по сигнатуре и размеру, но полной проверки декодирования файла нет.
- Изменение состояния задания выполняется по одному `id` после проверки family/kid на чтении; нужна проверка на коллизии ID и усиление условий записи.

Это **признаки риска**, а не доказанные эксплойты. Автоматическая проверка не заменяет ручной security review, тест на двух семьях и проверку сервера Beget.

## Приоритет исправлений
1. **P0:** отзыв токенов устройств, удаление семьи и связанных записей, правила удаления SQLite/WAL/бэкапов.
2. **P0:** тест изоляции семей при одинаковом ID задания и корректность UPDATE по семье/ребёнку.
3. **P0:** ограничение перебора приглашений/setup-кода, журналирование ошибок без токенов и фото.
4. **P1:** убрать длительное хранение bearer-токена в `localStorage`, оценить XSS/CSP.
5. **P1:** валидировать декодирование JPEG и ограничивать ресурсную стоимость обработки.
6. **P1:** проверить HTTPS, страну хранения данных, политику согласий и правовые основания у юриста.
