# Постоянный локальный диспетчер «ЯмогУ!» (31.10.2026)

Цель — снять необходимость постоянно писать «продолжай». Это **локальный процесс**, а не обещание, что разговор в ChatGPT выполняется бесконечно.

## Уже разрешённые автоматические действия

- Диспетчер проверяет очередь каждые 30 секунд и обновляет heartbeat каждые 10 секунд.
- Проверка безопасности F-005 (read-only): читает только `server/photos.py` и `js/photos.js` из локального пилота; при семи открытых рисках пишет статус `blocked`. Это не разрешение релиза.
- QA A-04 (read-only): `npm run check:legal` и `npm test` в изолированной ветке.
- Каждый разрешённый тип запускается **при изменении входных файлов**; без изменений — не чаще одного раза в 6 часов.
- Все результаты фиксируются по реальным событиям `running / finished / failed / blocked`, время и PID. В API центра управления есть heartbeat диспетчера.
- Одновременно выполняется максимум одно задание. Нет бесконечной серии Codex-вызовов и трат на модель без очереди.

## Важные ограничения

Автоматический **код-агент пока отключён**: для него нужен проверенный механизм изолированных worktree, ограничений по файлам, QA-ревью и согласований. Не подменять активный мониторинг утверждением, будто агент непрерывно пишет код.

Диспетчер не меняет пользовательские данные, не запускает деплой, не покупает услуги, не сливает PR и не назначает `LEGAL_APPROVED`. Он не хранит токены и фотографии детей. В автозапуске Windows работает **только после входа пользователя в систему** и пока ноутбук включён, а сессия запущена.

## Как увидеть работу

- При входе в Windows запускается `Yamogu_Agents_Autostart.cmd` из личной папки Startup.
- Панель: http://127.0.0.1:18766
- Рабочий стол: `Yamogu_LIVE.cmd` для ручного запуска, если диспетчер не включился.
- Очередь: `docs/agents/AUTO_QUEUE.json`. Для каждого типа есть явное `enabled`; новые произвольные команды из JSON не исполняются.
- Временные журналы без чувствительных данных: `%TEMP%\\yamogu-agent-monitor\\events.jsonl`, `scheduler.json`, `supervisor.json`.
- Остановить можно закрытием окна диспетчера или завершением его процесса Node.js; удалить файл из Startup для отключения автозапуска.

**Проверки на момент оформления:** Node.js-проверка синтаксиса; ранее 17/17 тестов QA и 12 пунктов security-аудита. Наличие рабочего процесса после входа в Windows и HTTP-страницы проверяется отдельно. До этого момента **не утверждать, что диспетчер сейчас запущен**.
