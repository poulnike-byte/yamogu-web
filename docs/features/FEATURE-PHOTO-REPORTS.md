# F-005 — Фотоотчёт: сбор, проверка и хранение
Версия: 0.1 (31.10.2026). Статус: DRAFT — нуждается в проверке юристом РФ.

## Назначение и роли
Ребёнок фотографирует результат задания (обязательно или по желанию), родитель рассматривает, подтверждает либо возвращает с подсказкой. Нет наказания за пропуск.
Коды приглашения одноразовые, действуют 10 минут. Родитель видит фото своей семьи, ребёнок — только свои задачи.

## Код и модель
js/photos.js, js/app.js, server/photos.py. Состояния: open → pending → done либо pending → open.
Клиент сжимает изображение в JPEG (максимум 1200 px), сервер допускает до 950 КБ. Задания: family, kid, title, criteria, coins, xp, state, revision и фото.

## Текущая политика удаления на сервере
- При подтверждении или возврате фото немедленно очищается из поля SQLite.
- Через 14 суток после отправки непринятого фото автоматическая очистка удаляет фото, сохраняя задачу, состояние и историю.
- Очистка выполняется при обращении к API и ежедневным systemd timer.
- Когда фото уже удалено, задача остаётся pending: родитель всё ещё может подтвердить её без изображения; требуется отдельное UX-решение.
- Файлы в галерее пользователя сервер не удаляет.
- **Важно**: логическое удаление из SQLite не гарантирует стирание старых страниц БД, WAL, снимков и резервных копий. Полный протокол очистки и бэкапов ещё не готов.

## Требования до публичного выпуска
1. Подтвердить фактическую страну ЦОД Beget и договоры на обработку данных.
2. Юрист РФ: правовое основание, согласие родителя, политика ПД, РКН, трансграничность и права на изображение.
3. Реализовать полное удаление данных семьи, отзыв детского устройства, защиту от перебора приглашений.
4. Утвердить сроки резервных копий и процедуру удаления.
5. В UI показывать срок хранения и факт удаления изображения.
6. Тесты: другая семья не видит фото, повторная награда невозможна, истёкшее фото удаляется, задача сохраняется.
